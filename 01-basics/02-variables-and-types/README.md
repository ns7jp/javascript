# 変数とデータ型

## この章で学ぶこと

- 変数（値を入れておく箱のようなもの）とは何か
- `let` / `const` / `var` の違いと、それぞれをいつ使うべきか
- JavaScriptにあるプリミティブ型（基本のデータの種類）の一覧と意味
- `typeof` 演算子を使って、値の型（種類）を調べる方法
- 型が違う値を扱うときに、エラーを起こさないための考え方

## 解説

### 変数とは何か

変数（へんすう）とは、値（数値や文字列など）を入れておくための「名前つきの箱」のようなものです。プログラムの中で、同じ値を何度も使い回したり、計算の途中結果を覚えておいたりするために使います。

```js
let age = 25;
console.log(age); // 25
```

上の例では、`age` という名前の変数を作り、そこに `25` という数値を入れています。

### let / const / var の違い

JavaScriptには、変数を宣言する（作る）ための書き方が3種類あります。

```js
let score = 80;    // 後から値を変更できる変数
const pi = 3.14;   // 後から値を変更できない変数（定数）
var oldStyle = 1;  // 昔の書き方（今はほとんど使わない）
```

それぞれの特徴を整理します。

| キーワード | 再代入（値の変更） | いつ使うか |
|---|---|---|
| `const` | できない | 基本はこれを使う。値が変わらないものに使う |
| `let` | できる | 値を後で変更する必要があるときだけ使う |
| `var` | できる | 古いJavaScriptの書き方。今は新しく書くコードでは使わない |

例えば、`const` で作った変数に別の値を入れようとすると、エラーになります。

```js
const pi = 3.14;
pi = 3.15; // エラー！ TypeError: Assignment to constant variable.
```

一方、`let` は値を変更できます。

```js
let score = 80;
score = 90; // OK。scoreの中身が90に更新される
console.log(score); // 90
```

**なぜ `const` を基本にするのか**という点も重要です。「この変数は途中で書き換わらないはず」ということが `const` を使うだけではっきりします。もし後から間違って値を変更するコードを書いてしまっても、`const` であればエラーになってすぐに気づけます。これは、意図しないバグを防ぐための工夫です。逆に、カウンター（数を数える変数）やループの途中で更新する値など、「後で変わることが分かっている」場合にだけ `let` を使います。

`var` は、JavaScriptの初期からある古い書き方です。`var` には「意図しない範囲まで変数が有効になってしまう」という分かりにくい弱点があるため、現在のJavaScriptでは基本的に `let` と `const` だけを使い、`var` は使わないのが一般的です（このREADME以降の教材でも `var` は使いません）。

### プリミティブ型（基本のデータの種類）

JavaScriptの値には「型（かた）」という種類があります。型が違うと、扱い方や計算のされ方が変わってきます。まずは、これ以上分解できない基本の型である**プリミティブ型**を紹介します。

```js
const name = 'たかし';       // string型（文字列）
const age = 25;              // number型（数値）
const isStudent = true;      // boolean型（真偽値。trueかfalseのどちらか）
const nothing = null;        // null型（「値が空である」ことを意図的に表す）
let notYetSet;                // undefined型（まだ値が代入されていない状態）
const bigNumber = 9007199254740993n; // bigint型（とても大きな整数を正確に扱う型）
const uniqueKey = Symbol('id'); // symbol型（絶対に他と重複しない値を作る型）
```

それぞれ簡単に説明します。

- **string（文字列型）**: `'こんにちは'` のように、文字の並びを表す型です。シングルクォート `'...'`、ダブルクォート `"..."`、バッククォート `` `...` `` のいずれかで囲みます。
- **number（数値型）**: `25` や `3.14` のような数値を表す型です。JavaScriptには整数専用の型はなく、整数も小数も `number` 型として扱われます。
- **boolean（真偽値型）**: `true`（真）か `false`（偽）のどちらかしか取らない型です。「条件に合っているかどうか」を表すときに使います。
- **null**: 「値が存在しない」ということを、プログラマーが意図的に表すための値です。「まだ何もない」ではなく「空であると分かっている」状態を表します。
- **undefined**: 変数を宣言したけれど、まだ値を入れていない状態です。JavaScriptが自動的に設定する値で、プログラマーが最初から意図して入れるものではありません。
- **bigint（ビッグイント型）**: `number` 型では正確に扱えないほど大きな整数を扱うための型です。数値の末尾に `n` をつけて表します（例: `9007199254740993n`）。サーバー構築の学習の中ではあまり使う機会は多くありませんが、存在は知っておきましょう。
- **symbol（シンボル型）**: 必ず他とは重複しない、一意な値を作るための型です。オブジェクトの中で「絶対に他とかぶらない目印」が欲しいときなどに使いますが、初心者のうちは「そういう型がある」程度の理解で十分です。

### typeof演算子で型を調べる

`typeof` は、値や変数の型を文字列として教えてくれる演算子（値を使って何かの処理をする記号や命令のこと）です。

```js
console.log(typeof 'こんにちは'); // "string"
console.log(typeof 25);           // "number"
console.log(typeof true);         // "boolean"
console.log(typeof undefined);    // "undefined"
console.log(typeof null);         // "object" （実はこれはJavaScriptの有名な仕様上のクセです）
console.log(typeof 10n);          // "bigint"
console.log(typeof Symbol('x'));  // "symbol"
```

ここで注意したいのが `typeof null` の結果です。本来は `"null"` と返ってきそうなものですが、歴史的な経緯（大昔のJavaScriptの実装の名残）により `"object"` という結果になります。これはJavaScriptにおける有名な「言語仕様のクセ」として知られていて、初心者がつまずきやすいポイントの1つです。

### 型が違う値の扱いに注意する

JavaScriptは、型が違う値同士でも、ある程度自動で変換して計算しようとする性質があります。これを**暗黙的な型変換**と呼びます。

```js
console.log(1 + '2');   // "12" （数値の1が文字列に変換されて連結される）
console.log('5' - 2);   // 3    （文字列の'5'が数値に変換されて引き算される）
```

このように、`+` や `-` などの演算子は、型によって結果が大きく変わることがあります。特に `+` は「文字列の連結」にも「数値の足し算」にも使われるため、意図しない結果になりやすいポイントです。

そのため、関数の中で「本当に数値が渡されているか」を事前にチェックしておくことは、バグを防ぐ上でとても大切です。

```js
function sumSafely(a, b) {
  // 事前に型をチェックしておくことで、
  // 意図しない計算結果（例: "12" のような文字列連結）を防ぐ
  if (typeof a !== 'number' || typeof b !== 'number') {
    throw new Error('sumSafelyには数値を渡してください');
  }
  return a + b;
}

console.log(sumSafely(2, 3)); // 5
sumSafely('2', 3); // エラー！ Error: sumSafelyには数値を渡してください
```

このように、「関数に渡ってくる値が期待通りの型かどうか」を確認してからエラーを `throw`（投げる、発生させる）することで、後から原因が分かりにくいバグを未然に防ぐことができます。サーバー構築の現場では、設定ファイルの値や外部から受け取ったデータの型が期待通りとは限らないため、こうした「値の検証」の考え方は非常に重要です。

## つまずきやすいポイント

- **`const` は「値が絶対に変わらない」という意味だと誤解しがち**: 正確には「変数に別の値を再代入できない」という意味です。オブジェクトや配列を `const` で宣言した場合、変数自体を別のものに入れ替えることはできませんが、オブジェクトや配列の中身（プロパティや要素）を変更することは可能です（この点は後の章で詳しく扱います）。
- **`null` と `undefined` を同じものだと思ってしまう**: `undefined` は「まだ値が設定されていない」という自動的な状態、`null` は「値が空であるとプログラマーが意図的に設定した」状態です。似ていますが、意味と使われる場面が違います。
- **`typeof null` が `"object"` になることを知らずに混乱する**: 前述の通り、これはJavaScriptの有名な仕様上のクセです。「`null` かどうか」を調べたいときは `typeof` ではなく `値 === null` のように比較する方が確実です。
- **`1 + '2'` のような暗黙的な型変換の結果を予測できない**: `+` は数値の足し算にも文字列の連結にも使われるため、型を意識せずに計算すると、意図しない結果（数値のつもりが文字列になっている、など）になりがちです。困ったときは `typeof` で実際の型を確認する癖をつけましょう。

## 演習問題

`exercise.js` に、次の2つの関数を実装してください。

1. `describeType(value)`
   - 引数 `value`（どんな型の値でも良い）を受け取る
   - `typeof value` の結果を使って、`"これは<型名>型です"` という日本語の文字列を `return` する
   - 例: `describeType(25)` は `"これはnumber型です"` を返す
   - 例: `describeType('こんにちは')` は `"これはstring型です"` を返す
   - 例: `describeType(true)` は `"これはboolean型です"` を返す
   - 例: `describeType(undefined)` は `"これはundefined型です"` を返す

2. `sumSafely(a, b)`
   - 引数 `a` と `b` を受け取る
   - `a` と `b` の**両方が** `number` 型であれば、`a + b` の計算結果を `return` する
   - どちらか一方でも `number` 型でなければ、意味の分かるメッセージ（例: `'sumSafelyには数値を渡してください'` など）をもった `Error` を `throw` する
   - 例: `sumSafely(2, 3)` は `5` を返す
   - 例: `sumSafely('2', 3)` はエラーを `throw` する
