# 実行環境とJavaScriptの基本

## この章で学ぶこと

- Node.js（ノード・ジェイエス）とは何か、なぜサーバー構築の学習でJavaScriptを使うのか
- ターミナル（コマンドを入力する黒い画面）から `node ファイル名.js` でプログラムを実行する方法
- 画面に文字を表示する `console.log` の使い方
- コメント（プログラムの中に書くメモ）の書き方
- 関数（処理をひとまとめにした部品）を作って呼び出す、という基本的なプログラムの流れ

## 解説

### Node.jsとは何か

JavaScript（ジャバスクリプト）は、もともと「Webブラウザの中で動く」プログラミング言語として生まれました。たとえば、Webページのボタンを押したら画面の色が変わる、といった動きを作るための言語です。

しかし今では、**Node.js** という仕組みを使うことで、ブラウザがなくても、パソコンやサーバー（インターネット上でずっと動き続けているコンピューター）の中で直接JavaScriptを実行できるようになりました。

サーバー構築エンジニア（インフラエンジニア）を目指すうえで、Node.jsはとても重要です。なぜなら、

- サーバーを操作する自動化スクリプト（決まった作業を自動でやってくれるプログラム）を書くのに使える
- Webサーバー（Webページやデータを配る役割のプログラム）そのものをJavaScriptで作れる
- 多くの現場で実際に使われている、実践的な技術である

という理由からです。この教材では、Node.jsを使ってJavaScriptの基本からサーバー構築に必要な知識までを学んでいきます。

### なぜ `node ファイル名.js` で実行するのか

プログラムのコードを書いただけでは、コンピューターは何もしてくれません。書いたコード（テキストファイル）を「実行してください」とコンピューターに指示する必要があります。

たとえば `hello.js` という名前のファイルに次のように書いたとします。

```js
console.log('こんにちは、世界！');
```

このファイルは、ただのテキストファイルです。メモ帳で開いても文字が書いてあるだけで、何も起こりません。これを実際に動かす（＝実行する）ためには、ターミナル（キーボードでコマンドを打ち込む画面）で次のように入力します。

```bash
node hello.js
```

この「`node`」という部分が、「Node.jsという実行エンジンを使って、このファイルの中身をJavaScriptとして読み取り、上から順番に実行してください」という命令になっています。実行すると、ターミナルに次のように表示されます。

```
こんにちは、世界！
```

つまり、プログラミングの基本的な流れはこうです。

1. テキストエディタ（コードを書くためのソフト）でコードを書く（`.js` ファイルとして保存する）
2. ターミナルで `node ファイル名.js` を実行する
3. 上から下へ、コードが1行ずつ順番に実行される
4. `console.log(...)` と書かれた場所があれば、その中身がターミナルの画面に表示される

このサイクル（書く→実行する→結果を見る→直す）を繰り返しながらプログラムを作っていくのが、プログラミングの基本的な作業スタイルです。サーバー構築の現場でも、スクリプトを書いて実行し、結果を確認して修正する、という同じ流れで作業します。

### console.log で画面に表示する

`console.log(...)` は、カッコの中に書いた値をターミナルの画面に表示するための命令です。「console（コンソール）」はターミナル画面のこと、「log（ログ）」は記録・出力という意味です。

```js
console.log('メッセージを表示します');
console.log(1 + 2); // 計算結果も表示できる
```

プログラムが「今どんな状態なのか」「計算結果はどうなったのか」を確認したいときに、非常によく使う命令です。バグ（プログラムの不具合）を調べるときにも、まずは `console.log` で値を表示して確認する、というのが基本のやり方になります。

### コメントの書き方

コメントとは、プログラムの中に書く「人間向けのメモ」のことです。コメントに書いた内容はJavaScriptとしては実行されません（無視されます）。あとで自分がコードを見返したときや、他の人がコードを読むときに「これは何のための処理か」を伝えるために書きます。

コメントには2種類の書き方があります。

```js
// これは1行だけのコメントです。この行の "//" より右側は実行されません。

/*
  これは複数行にわたるコメントです。
  長い説明を書きたいときに使います。
  この範囲は全て実行されません。
*/

console.log('この行は実行されます'); // 行の後ろにコメントを書くこともできる
```

コメントは「コードを書いた本人にしか分からない意図」を残すためにとても重要です。特にインフラの現場では、「なぜこの設定にしたのか」「なぜこの手順が必要なのか」を後から見返せるようにしておくことが、トラブル対応のスピードを大きく左右します。

### 関数を作って使う

関数（かんすう）とは、「ある処理をひとまとめにして、名前をつけたもの」です。何度も同じ処理を書かずに済むように、部品化しておくイメージです。

```js
// greetという名前の関数を定義する（=作る）
// nameという引数（ひきすう。関数に渡す値のこと）を受け取る
function greet(name) {
  return `こんにちは、${name}さん！`;
}

// 関数を呼び出す（=実際に使う）
const message = greet('田中');
console.log(message); // "こんにちは、田中さん！" と表示される
```

ポイントを整理します。

- `function 関数名(引数) { ... }` という形で関数を定義（作成）します
- 関数の中の `return` は、「この値を呼び出し元に返す」という意味です。`return` された値が、関数を呼び出した場所の結果になります
- `` `こんにちは、${name}さん！` `` のようにバッククォート（`` ` ``）で囲んだ文字列の中に `${変数名}` と書くと、その変数の中身を文字列に埋め込めます。これを**テンプレートリテラル**と呼びます

もう一つ、数値を足し算する関数の例も見てみましょう。

```js
function add(a, b) {
  return a + b;
}

console.log(add(2, 3)); // 5 と表示される
```

`add(2, 3)` のように関数を呼び出すと、`a` に `2`、`b` に `3` が渡され、関数の中では `a + b`（つまり `2 + 3`）が計算され、その結果 `5` が `return` されます。

## つまずきやすいポイント

- **ファイルを保存し忘れる**: コードを編集しても、ファイルを保存（Save）しないと `node ファイル名.js` を実行しても古い内容のまま実行されてしまいます。実行前には必ず保存したか確認しましょう。
- **実行するファイルのパスを間違える**: `node hello.js` は、今いるディレクトリ（フォルダ）に `hello.js` がある場合にしか動きません。別のフォルダにいる場合は `node フォルダ名/hello.js` のように、ファイルまでの道筋（パス）を正しく書く必要があります。
- **`console.log` と `return` を混同する**: `console.log` は「画面に表示するだけ」で、関数の結果として値を返しているわけではありません。`return` は「呼び出し元に値を返す」ことです。この2つは役割が違うので、関数の中で `console.log` しか書いていないと、その関数を呼び出しても値を受け取ることができません（`undefined` になります）。
- **コメントの閉じ忘れ**: `/* ... */` の複数行コメントは、閉じる `*/` を書き忘れると、その後のコード全体がコメント扱いになってしまい、意図しない動作になります。書いたら必ず閉じ忘れがないか確認しましょう。

## 演習問題

`exercise.js` に、次の2つの関数を実装してください。

1. `greet(name)`
   - 引数 `name`（文字列）を受け取る
   - `"こんにちは、<name>さん！"` という文字列を `return` する
   - 例: `greet('田中')` は `"こんにちは、田中さん！"` を返す

2. `add(a, b)`
   - 引数 `a` と `b`（どちらも数値）を受け取る
   - `a + b` の計算結果を `return` する
   - 例: `add(2, 3)` は `5` を返す
